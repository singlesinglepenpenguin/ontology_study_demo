# 采购 Demo 功能说明

这是一个可以在本机打开的采购教学系统。里面的供应商、订单和金额都是预先放好的教学数据，不是真实企业数据，也不是 Palantir 官方产品。

打开 http://127.0.0.1:8000 ，用下面三个账号登录。密码都是 `demo123`。服务重启后需要重新登录。每个账号只能看到自己的聊天记录；变更申请是三个人共用的业务单据，审批员凭申请编号处理，不需要打开采购员的对话。

左侧有五项：首页、对话、本体配置、数据明细、模型配置、用户管理。

## 本体配置

这里展示当前已经加载的采购本体，启动后自动生效。不需要再点激活，也不能在页面上上传或切换成别的本体。

可以展开查看 11 类业务事物、它们之间的关系、8 项计算和 3 项操作。这里看的是「有哪些种类、怎么关联」，不是某一条具体订单。具体记录到「数据明细」里看。

| 看到的名称 | 含义 | 初始有多少 |
|---|---|---:|
| Supplier | 供应商 | 8 |
| Material | 物料 | 6 |
| Customer | 客户 | 12 |
| Order | 客户销售订单 | 48 |
| PurchaseOrder | 采购单 | 18 |
| AllocationPlan | 分货计划 | 10 |
| AllocationBatch | 分货批次 | 21 |
| SupplierScore | 供应商评分 | 10 |
| SupplyOption | 备选供货报价 | 36 |

销售订单通过编号关联客户、物料、供应商和原来的采购单。销售金额和采购金额分开计算，不会加在一起。

页面上还能看到这些能力：

| 能力 | 用来做什么 |
|---|---|
| 采购全景 | 看各类数量、延期影响和库存 |
| 延期影响 | 看某家供应商、某种物料晚到后，哪些销售订单受影响 |
| 评估一个报价 | 看备选供应商能不能按时、按量供货，要多花多少钱，预算够不够 |
| 比较多个报价 | 同一家原供应商、同一种物料的候选方案放在一起比较 |
| 沿订单追溯 | 从一张销售订单找到客户、物料、供应商、原采购单、批次、计划和历史评分 |
| 查看申请 | 看某张变更申请现在到了哪一步 |
| 供货风险分 | 按既定规则给分货计划打分，这是规则分数，不是预测概率 |
| 汇总和图表 | 按供应商、物料、状态汇总；销售订单还可以按客户汇总 |
| 提交变更 | 提出改用某个备选报价 |
| 审批变更 | 批准别人提交的申请 |
| 执行变更 | 把已批准的申请真正写到订单上 |

## 数据明细

这里直接查看当前业务数据，和对话里用的是同一份数据。可以按对象类型切换，按编号等值筛选，翻页，并看原始记录。销售订单还会多两列核对：供应商延期了几天、这张订单算不算受影响。

页面只供查看。不能在这里改数，也不能自己写查询语句。

有四个快捷范围，方便和对话结果对照：

## 模型配置

对话使用 DeepSeek。模型名称、接口地址已经写在项目里，网页的「模型配置」可以查看这项设置。

这个 Demo 不在网页里更换模型，也不在网页里测试连通性。要让对话工作，请使用你自己的 DeepSeek API Key：把 `.env.example` 复制为同目录的 `.env`，填入 `DEEPSEEK_API_KEY`。`.env` 只留在你的电脑上，不会进入这份代码仓库。

没有 Key 时，页面和已有数据仍可打开；一提问，对话会因为连不上模型而失败。

## 用户管理

这里列出三个教学账号，以及每个角色可以查询的对象、可以做的计算和可以执行的操作。不能在页面上新增、删除或修改账号，也没有单独的管理员登录。

三个账号都能查看全部教学数据，也都能做上面的查询和计算。差别在于谁可以改业务。

| 账号 | 登录名 | 能做的事 | 不能做的事 |
|---|---|---|---|
| 查询员 | viewer | 看数据、汇总、追溯、评估方案、看申请进度 | 提交、审批、执行 |
| 采购员 | buyer | 查询员能做的全部事情；预览并提交变更；执行已经批准的申请 | 审批 |
| 审批员 | approver | 查询员能做的全部事情；审批待处理的申请 | 提交、执行；不能审批自己提交的申请 |

改供货要走完三步，而且每一步都要在对话里先看预览，再由本人确认：

1. 采购员提交：说明原供应商和要用的备选报价。
2. 另一位审批员批准。
3. 采购员执行。执行前会再检查报价、数量和预算有没有在审批后变过；变过就要重新提交。

询问「哪个方案好」只给出计算结果，不会改订单。执行之后，受影响的销售订单会改到新的供货安排，并扣掉报价的可用数量和预算。原来的采购单仍保留，当作历史来源。这里不会向真实采购系统下单。

聊天记录按账号分开。采购员不能接着查询员的对话去执行。退出或切换账号后，上一账号还没写完的回答不会进到新账号的页面。
