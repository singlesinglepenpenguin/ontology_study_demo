# 独立运行验证

验证日期：2026-10-16。环境：macOS、Python 3.14.7、Node.js 24.20.0。

## 已执行

1. 全部运行源码、配置、种子数据和前端构建产物放入 `ontopilot_supplier/`，创建该目录自己的虚拟环境并按锁文件安装依赖。
2. 删除本地整个 `repos/` 后，从准备发布的 Git 提交全新 clone 到临时目录。clone 内没有个人 `.env`、业务数据库、既有对话或 `node_modules`。
3. 在 clone 内新建另一个虚拟环境，按 README 安装依赖；确认 `api`、`ontopilot`、`runtime` 的导入路径全部属于 clone 自身。
4. `run.py check` 通过；35 项程序测试通过，覆盖业务计算、审批执行、回滚、账号与会话隔离、确认绑定、预览过期和数据明细。
5. clone 使用自带 `frontend/dist` 启动服务，不安装 Node.js 依赖也能打开采购页面。测试密钥仅通过进程环境传入，没有写进 clone 或 Git。
6. 真实 DeepSeek 流式聚合调用 `aggregateOrders`，返回 48 张销售订单、883,250 元，并产生实际函数轨迹和图表事件。
7. Chrome + 真实 DeepSeek 验证：查询员查询 → 采购员提交 → 未批准执行被拒 → 审批员批准 → 采购员原会话读取最新状态 → 采购员确认执行。申请经过 pending → approved → executed，O1 改由 SUP-006 供货，额外预算从 30,000 降为 10,000 元。写入只发生于 clone 的测试数据库。
8. 在独立目录执行 `npm ci` 和默认 `npm run build` 通过；默认构建即采购模式，不需要旧补丁脚本或额外环境变量。

全新 clone 的浏览器验证还发现并修复了一项首次启动问题：原本按配置目录枚举顺序提供两份本体，前端可能选中未加载的旧本体，导致 400。现在只提供当前实际加载的 `ontology_schema.yaml`，并有回归测试。
