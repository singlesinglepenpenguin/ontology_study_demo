# 五分钟本地演示

这是本次研究配套的原创教学代码，不是 Palantir 软件，也不是一个已经接入 LLM 的 Agent。它使用规则模拟规划步骤，展示对象、关系、计算函数和受控操作如何配合。所有业务数据均为虚构。

需要 Python 3.10 或以上，不需要安装依赖、联网或密钥。从研究文件夹运行：

```bash
# 1. 查看提案：两张订单，受影响销售额 100000 元，毛利口径 30000 元，额外采购成本 2000 元
python3 demo/demo.py

# 2. 预算缩小：feasible 将为 false
python3 demo/demo.py --budget 1000

# 3. 分析员尝试审批：拒绝，退出码 1
python3 demo/demo.py --approve

# 4. 经理审批：将订单供应商改为 S2，写入 state.json 与其中的 audit
python3 demo/demo.py --role manager --approve

# 5. 再查询：不再有受影响订单，不能重复执行采购方案
python3 demo/demo.py
```

重新演示时可用 `--state demo/第二次演示.json` 指定一个尚不存在的文件；各次命令使用同一路径即可。已存在的状态会保留。

## 演讲时指给观众看

| 本体概念 | 代码中的位置 | 看点 |
|---|---|---|
| 对象与属性 | `seed()` | 供应商有延期天数，订单有金额、数量和交付缓冲 |
| 关系 | 订单的 `supplier` 字段 | 通过供应商 ID 找到受影响订单 |
| 函数 | `propose()` | 程序计算金额、库存和预算约束 |
| Action | `apply_action()` | 审批后才能改变订单供应商 |
| 留痕 | `audit` | 记录角色、时间、修改前状态与提案 |

假设两张订单各采购同一种商品、每个销售单位需要一个采购单位，S2 的商品完全可替代且能及时交货。这里没有建模合同罚金、税费、物流、产品认证或多币种。

## 如何升级成真正的 AI Agent

把查询和测算封装为只读工具，让模型根据自然语言选择工具、引用返回值并解释方案；把提交提案封装为另一工具。执行仍走 `apply_action()` 对应的后端校验，审批身份来自登录系统。可参考已克隆的 Neo4j Agent 的工具组织方式。

当前 `--role` 只是教学角色开关，没有身份认证；JSON 文件也没有并发事务、不可篡改审计或企业权限。这些演示限制不能被当作生产能力。真实系统还应把审批绑定到提案版本，验证过期状态，并处理外部系统写入失败。
