# 真实 Agent 问答验证摘录

本记录来自实际 DeepSeek API 调用，经上游 OntoPilot 的 LangGraph Agent 和本例 Runtime 执行。模型请求名称为 `deepseek-v4-flash`，使用非思考模式；没有用规则模拟冒充模型回复。数据均为原创虚构教学数据。

## 延期影响

问题：查询 S1 与关联订单，计算受影响订单、金额与需求。

实际成功工具轨迹：

```text
object_query:Supplier
object_query:Order
function:assessSupplierDelay
```

模型回答摘录：

> 受影响订单：O1、O2；受影响销售金额合计：100,000 元；受影响总需求：100 件。

回答同时识别 O3 缓冲 10 天，本次不受 7 天延期影响，并说明受影响销售额不是已经发生的损失。

## 替代方案与预算

问题：OPT-S2-P1 能否替代 S1，额外成本是多少？预算只有 1,000 元时如何？

实际成功工具轨迹：查询 SupplyOption、Supplier，随后两次调用 `assessSupplyOption`，分别使用默认预算和收紧预算。

| 项目 | 模型回答与函数结果 |
|---|---|
| 覆盖需求 | 可供 100 件，满足 O1、O2 的 100 件需求 |
| 额外成本 | 2,000 元 |
| 预算 3,000 元 | 可行 |
| 预算 1,000 元 | 不可行，超出额外采购预算 |

未提交、审批或执行变更。

## 关系查询

问题：沿 O1 的关系查询客户、商品和供应商。

实际成功工具：`traceOrderRelations(orderId="O1")`，在 ObjectStore 中沿已定义外键关系遍历。

| 关系 | 模型返回编号 | 名称 |
|---|---|---|
| Order.customer | C1 | 客户甲 |
| Order.product | P1 | 标准商品 |
| Order.supplier | S1 | 原供应商甲 |
